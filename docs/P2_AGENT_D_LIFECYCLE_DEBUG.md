# Agent D 分发单：Lifecycle & Debug

## 1. 任务目标

补齐账本生命周期与调试能力，保证按账本队列方案可维护、可验证。

## 2. 背景上下文

- 队列文件已改为 `classify_queue/{ledger}.json`
- 删除/重命名账本时，队列文件必须同步处理
- 需要调试命令支持按账本观察队列状态
- 最新基线（2026-03-23）：Agent A 已验收通过，调试命令已具备基础能力

## 2.1 实施前基线确认（2026-03-23）

- `ClassifyQueue` 已提供 `removeByLedger` 与 `renameLedger` 能力
- `window.__DEBUG_TOOLS__` 已有 `viewQueue/clearQueue/testQueuePriority` 调试入口
- 当前缺口：`LedgerManager` 生命周期流程尚未接线调用上述队列生命周期方法

## 3. 负责范围（只做这些）

1. 账本删除时删除对应队列文件（如存在）
2. 账本重命名时重命名对应队列文件（如存在）
3. 调整调试工具：支持查看当前账本队列与指定账本队列
4. 补充与更新相关测试脚本/验证步骤

## 4. 禁止越界（不要做）

- 不改队列冲突升级规则
- 不改 AI Engine 消费范围核心逻辑
- 不改触发策略与 UI 交互
- 不新增自动触发入口

## 5. 建议涉及文件

- `src/core/services/LedgerManager.ts`
- `src/core/services/LedgerService.ts`
- `src/debug/*` 与 `window.__DEBUG_TOOLS__` 绑定位置

## 6. 验收标准

1. 删除账本后无残留队列文件
2. 重命名账本后队列文件路径同步迁移
3. 调试工具可正确查看当前账本队列
4. 不影响已有 P0/P1 调试命令可用性
5. 生命周期接线后，不影响 B/C 的当前账本消费约束

## 7. 交付物

- 生命周期处理代码变更
- 调试命令变更说明
- 回归检查清单（避免误删/误改其他账本数据）
- 接线前后差异说明（明确哪些是补线，哪些是已有能力复用）
